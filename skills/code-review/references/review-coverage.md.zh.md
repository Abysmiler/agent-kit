## 覆盖模型

按三层应用覆盖：

1. **基线（baseline）**：对每个非平凡变更检查意图、正确性、复杂度、测试、安全基础和意外范围。
2. **触发透镜**：仅当变更触及相应边界时才深化评审。
3. **影响锥（impact cone）**：纳入那些其假设、契约、调用方或运维行为可能被该变更作废的未变更代码。

将每个被选中的透镜记录为 `Reviewed`、`Partial`、`Skipped` 或 `Needs Follow-up`。被跳过的透镜必须说明其不可能被该变更触发的理由。

按以下维度排定优先级：

- 用户或业务影响。
- 安全、隐私、数据、资金或可用性暴露。
- 可能性与现实可触发性。
- 影响范围与可逆性。
- 证据强度。
- 缺陷是系统性的还是孤立的。

不要仅按行数、新奇程度或风格好恶来排定优先级。

## 基线透镜

应用于每个非平凡变更。

### 意图保真

- 确认 diff 实现了既定需求，且不含无关行为。
- 从测试、文档、调用方、UI 和既有契约中识别隐性需求与非目标。
- 检查是否存在"能运行但编码了错误业务含义"的实现。
- 将被移除的行为与兼容性承诺以及旧路径的使用者对照。

### 局部正确性

- 检查正常路径、非法输入、空输入、最大/最小值、缺失数据和部分失败。
- 检查分支条件、布尔取反、差一错误、默认行为和 fallthrough。
- 追踪错误传播与清理。
- 检查单位、时区、区域设置、货币、舍入、标识符、排序和序列化。

### 范围与代码健康

- 标记掩盖行为变更的无关编辑、大范围重写、死兼容代码和生成式扰动。
- 检查复杂度、状态、分支、依赖或公共暴露面是否不必要地增长。
- 在接受新的辅助函数、服务、适配器、hook、校验器或抽象之前，先搜索既有入口点。
- 依据实际行为核对注释与命名，而不仅依据作者的解释。

### 验证

- 对缺陷修复，寻找在变更之前会失败的回归测试。
- 核对断言测试的是外部有意义的行为。
- 检查必需的检查项；不要从摘要推断通过状态。
- 识别最重要的未测试不变量。

## 意图与领域语义

**触发条件：** 任何产品行为、业务规则、工作流、权利、计算、优先级排序、资格判定、计费、审核仲裁或状态迁移的变更。

检查：

- 权威产品规格与决策归属。
- 前置条件、后置条件、不变量和合法的状态迁移。
- UI、API、领域模型、持久化与下游集成之间的含义冲突。
- 在技术上看起来合法却违反策略的边界情形。
- 向后兼容性以及既有存量数据的行为。
- 部分完成、取消、重试和用户可见的恢复。
- 某个"回退"（fallback）是否悄悄改变了业务语义。
- 该变更是否绕过了既定的领域服务或策略层。

当正确性取决于未言明的策略选择时，升级为 `Needs Decision`（需要决策）。

## 数据与持久化

**触发条件：** schema、迁移、查询、事务、缓存、序列化、导入/导出、删除、保留期或存储行为的变更。

检查：

- 滚动部署期间的前向与后向兼容性。
- 迁移顺序、锁持续时间、表扫描、默认值、可空性、索引创建和回滚限制。
- 事务边界、隔离级别、丢失更新、写偏斜、重复写入和部分副作用。
- 幂等键、唯一性约束、外键和应用层假设。
- 数据丢失、截断、类型强转、编码、精度、时区转换和不可逆变换。
- 缓存失效、过期读、缓存键范围和租户/用户隔离。
- 分页、稳定排序、游标有效性和批量限制。
- 保留期、删除、恢复、审计日志和隐私义务。
- 新旧应用版本之间的读写兼容性。
- 导入/导出契约以及畸形或对抗性记录。

对破坏性变更和迁移要求显式证据。本地单元测试成功不足以证明。

## 状态、异步与并发

**触发条件：** 异步工作、UI 状态、后台任务、队列、worker、回调、定时器、订阅、流、锁、并行或共享可变状态的变更。

检查：

- 竞态条件、过期响应、重复提交、重入和乱序完成。
- 超时、导航、关闭或重试时的取消与清理。
- 在至少一次（at-least-once）基础设施上实现的恰好一次（exactly-once）假设。
- 跨进程重启与消息重投的幂等性。
- 锁范围、死锁、加锁顺序、饥饿和租约过期。
- 状态机迁移以及不可能或含义模糊的标志组合。
- 重试放大、惊群、毒消息和背压。
- 跨数据库、队列、网络和外部服务边界的部分成功。
- 事件顺序、去重、重放和版本兼容性。
- 资源泄漏：任务、套接字、文件句柄、订阅、goroutine/线程和临时文件。

当非正式阅读变得含糊时，优先使用状态迁移表或时序追踪。

## 安全、隐私与信任边界

**触发条件：** 公开输入、认证、授权、租户边界、文件、URL、命令、模板、反序列化、机密、日志、加密、webhook、集成或智能体/工具执行的变更。

检查：

- 每个可达分支上的身份认证。
- 标识符解析之后的对象级和动作级授权。
- 查询、缓存、任务和日志中的租户、组织、账户和用户隔离。
- 在信任边界处进行输入验证，而不仅在 UI 或调用方。
- 注入路径：SQL/NoSQL、shell、模板、路径、header、URL、LDAP、表达式和代码执行。
- SSRF、开放重定向、不安全抓取、DNS 重绑定和私网访问。
- 路径穿越、压缩包解压、符号链接、上传类型/大小和不安全的文件服务。
- 输出编码、XSS、内容嗅探和不安全的 Markdown/HTML 渲染。
- 会话固定、CSRF、令牌范围、令牌生命周期、吊销和重放。
- 通过代码、环境、日志、错误、遥测、缓存、构建产物或前端 bundle 暴露的机密。
- 敏感数据最小化、目的限制、保留、删除和可审计性。
- 加密算法、nonce/IV 使用、密钥管理、比较时序和不安全的自造加密。
- 速率限制、滥用控制、账户枚举和高成本操作。
- fail-open 行为与被吞掉的安全错误。

将每个安全发现锚定到资产、攻击者能力、可达路径和影响。没有可信的边界违反时，不要提交投机性的漏洞标签。

## 可靠性、运维与发布安全

**触发条件：** 部署、配置、环境变量、特性开关、服务依赖、重试逻辑、日志、指标、告警、健康检查、迁移或失败处理的变更。

检查：

- 配置默认值、缺失/非法值、环境一致性和机密边界。
- 特性开关的生命周期、定向投放、过期开关、kill switch，以及开关服务失效时的行为。
- 滚动部署期间跨版本的向后/前向兼容性。
- 应用、schema、队列和外部契约之间的部署顺序。
- 写入或迁移之后的回滚可行性。
- 重试策略、超时预算、抖动、熔断、回退语义和过载行为。
- 健康度/就绪度检查是否反映真实依赖就绪状态而不引发级联故障。
- 针对变更后关键路径的日志、指标、追踪和告警。
- 错误是否可行动、是否保留关联标识符且不泄漏机密。
- 优雅降级、紧急停用和运维恢复步骤。
- 启动/关闭行为与在途工作的处理。
- 事件响应与 runbook 影响。

将"回退"视为需要证据的语义变更；掩盖数据损坏或授权失败的回退不是韧性。

## 性能、容量与成本

**触发条件：** 对无界数据的循环、数据库访问、网络调用、大负载、缓存、渲染、序列化、后台处理或资源密集的智能体/模型调用发生变更。

检查：

- 相对真实输入规模的复杂度。
- N+1 查询、重复远程调用、本应有界并行却串行执行的工作，以及无界扇出。
- 分页、流式处理、批处理、负载大小、压缩和内存滞留。
- 查询计划、索引、选择性、表扫描和锁竞争。
- 缓存命中假设、踩踏防护、淘汰和一致性权衡。
- 冷启动、启动时间、bundle 大小、客户端渲染和主线程阻塞。
- 速率限制与第三方配额。
- token、模型、存储、计算和出口流量的成本放大。
- 基准测试的代表性，以及优化是否削弱正确性或安全性。

仅在具备可信规模或观测证据时报告性能问题。避免理论化的微优化意见。

## 架构与可维护性

**触发条件：** 共享抽象、模块边界、公共 API、横切关注点、重构、新增分层、大范围文件搬移或重复出现的生成式模式。

检查：

- 依赖方向，以及变更是否绕过既定边界。
- 领域状态、验证、错误和配置的单一事实来源。
- 重复的辅助函数、近乎相同的组件、并行的服务层和复制的测试。
- 只有一个真实用途且无高风险语义理由的新接口/工厂/配置。
- 上帝模块、超长函数、深嵌套分支、归属不清和循环依赖。
- 旧行为已不复存在的兼容层。
- 公共 API 膨胀，以及私有/局部作用域是否已足够。
- 内聚性：是否为了提示词便利而把无关职责放在一起。
- 耦合度：一处局部变更现在是否要求许多无关模块跟着改。
- 文档/ADR 漂移，以及未来维护者能否从仓库恢复意图。
- 该修复让下一次类似变更更容易，还是仅仅又加了一个特例。

谨慎应用"三次法则"。对于认证、权限、资金、时间、单位、持久化、错误处理等必须保持集中化的语义，共享抽象可以提前合理化。

## 依赖与供应链

**触发条件：** manifest、lockfile、生成代码、vendored 代码、构建脚本、包脚本、registry、容器、action、插件、MCP 服务器或外部二进制发生变更。

检查：

- 该依赖是否必要，原生/标准库/既有功能是否已足够。
- 包名、registry、来源、版本、维护状态、许可证和归属是否正确。
- 域名抢注（typosquatting）、依赖混淆、可变标签、未固定的 action/镜像和安装脚本。
- 相对预期变更的传递依赖与 lockfile 扰动。
- 破坏性 API 变更、运行时支持和平台兼容性。
- 构建期网络访问、生成产物、校验和、签名和溯源。
- CI 权限、令牌暴露、产物篡改和发布晋级。
- 漏洞修复是否真正移除可达风险，而不是让扫描器闭嘴。
- 来源与更新路径不清的生成或复制代码。

不要因为某个依赖的 API 听起来合理就接受它。从仓库或权威来源加以验证。

## 测试、CI 与验证完整性

**触发条件：** 行为变更、测试变更、CI/配置变更、扫描器变更、大范围 mock/fixture 变更，或智能体宣称成功。

检查：

- 该测试在变更之前是否会失败、之后是否会通过。
- 与变更相关的正常、失败、边界、权限、并发、迁移和回滚路径。
- 基于真实结果的断言，而不是仅靠 mock、调用计数、快照或生成结构。
- 在数据库、文件系统、队列、网络、浏览器和外部契约边界处的集成覆盖。
- 让不可能成立的系统通过测试的过度 mock。
- 不稳定的重试、测试顺序依赖、共享全局状态、时钟/随机性和竞态敏感性。
- 被删除的测试、被跳过的测试、被调低的阈值、被弱化的命令、被更改的触发器、`|| true` 或被删除的反向断言。
- 让变更文件绕过必需检查的 CI 路径过滤器和分支规则。
- 未解释行为变更就更新的生成基线或快照。
- 被禁用或被收窄的静态分析、类型检查、安全扫描和构建产物。
- 当仓库支持浏览器自动化或截图时，进行手动/UI 验证。

除非同等保护被证明已替换，否则将被削弱的验证视为阻塞项。

对高风险纯逻辑，考虑：

- 针对宽输入空间上不变量的基于性质的测试。
- 当变换应保持某种关系时使用蜕变测试。
- 对照先前实现或可信 oracle 的差分测试。
- 针对迁移密集行为、基于模型/状态机的测试。
- 在解析器、解码器、序列化器和安全边界处的模糊测试或微模糊测试。

## UI、可访问性与产品工作流

**触发条件：** UI、交互、样式、路由、表单、本地化、通知或面向用户的错误行为变更。

检查：

- 加载中、空、错误、禁用、提交中、已选中、过期、重试和离线状态。
- 键盘导航、焦点顺序/归还、标签、语义化控件、读屏器播报和对比度。
- 响应式行为、溢出、缩放、长文本、翻译文本、RTL 和减少动效。
- 重复提交、乐观更新、过期响应和导航时的取消。
- 破坏性操作的确认、撤销/恢复和明确的作用范围。
- 客户端与服务器之间表单验证的一致性。
- 本地化键、复数形式、日期、数字、货币和回退语言。
- 相对既有信息架构的视觉/交互漂移。
- 用脆弱的自定义控件替代浏览器原生行为。
- 新 UI 事件的遥测与隐私影响。

对实质性 UI 变更，可行时检查真实渲染行为或仓库支持的浏览器证据。

## 智能体与自动化变更

**触发条件：** AI 生成的变更；提示词、技能、AGENTS 文件、规则、hook、工作流、模型调用、MCP、连接器、浏览器工具、记忆、沙箱或自主修复的变更。

应用 `references/ai-agent-risk-catalog.md` 并检查：

- 模型与 harness 的组合行为，而不是孤立地看模型。
- 流入提示词或工具决策的不受信内容。
- 工具与网络权限、服务身份、令牌和审批门禁。
- 被解释为 shell、SQL、部署或破坏性动作的模型输出。
- 智能体修改自身指令、权限、校验器或完成判据的能力。
- 可被伪造、覆盖或过期失效的进度/状态产物。
- 只度量最终通过/失败而忽略轨迹、副作用或捷径的评测。
- 同一智能体既编写又评审的相关性盲区，以及缺失的独立验证。
- 看似权威却无溯源的生成依赖、配置、测试和文档。
- token/无界循环导致的钱包耗尽和自动化失控。

## 场景与证据模板

### 失败场景

```text
Stimulus: <input, event, attacker action, retry, deploy, or failure>
Environment: <version mix, load, tenant, degraded dependency, data shape>
Path: <entry point -> transformations -> persistence/side effect -> output>
Required invariant: <what must remain true>
Observed evidence: <code/test/runtime evidence>
Failure: <how the invariant can be violated>
Impact: <user/business/security/operations consequence>
```

### 发现证据

```text
Scope: <files, symbols, route, workflow>
Trigger: <specific reachable condition>
Proof path: <steps or call/data flow>
Disproof attempted: <guard, type, test, contract, runtime check>
Evidence: <references and command output>
Uncertainty: <what remains unknown>
Smallest fix direction: <not a speculative rewrite>
```

### 覆盖状态

```text
Lens: <name>
Trigger: <why selected>
Scope reviewed: <paths/workflows>
Evidence: <commands/references>
Status: Reviewed | Partial | Skipped | Needs Follow-up
Gap: <remaining risk>
```

## 应避免的低信号反馈

不要报告：

- 工具已强制的纯格式问题。
- 在无项目证据时偏好另一种同样有效的写法。
- 没有可达触发条件或受影响不变量的假设性问题。
- 对同一根因的每一处出现重复提交意见。
- 不指明缺失行为或 oracle 的"多加点测试"。
- 无可信规模或证据的"可以更快一点"。
- 在存在局部、可逆修复时提出大规模重写。
- 缺少资产、信任边界、路径和影响的安全标签。
- 未经独立验证就复制其他评审者的发现。
- 掩盖可行动风险的赞美、总结或教程式内容。
