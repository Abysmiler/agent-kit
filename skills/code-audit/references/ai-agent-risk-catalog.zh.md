# 面向系统审计的 AI-Agent 风险目录

当 AI agent 实质性参与创建、评审、测试、编写文档、部署或运维该仓库，或产品本身包含 agent 时，使用本目录。把模型、harness、仓库、工具、身份、数据、控制与人类工作流作为一个社会技术系统来审计。

## 审计方法

对每个适用的风险族：

1. 识别资产、用户、运维人员与特权操作。
2. 绘制 agent/模型/harness 的身份、工具、数据源、网络路径与持久状态。
3. 区分可信的控制指令与不可信内容。
4. 追踪现实的失败与滥用场景。
5. 检查结果与轨迹，而不仅是摘要。
6. 在可行处机械地验证护栏。
7. 记录剩余的人类判断与紧急控制。

不要从"AI 生成"的外观泛化推断。审计观察到的系统属性与证据。

## 代码库与架构风险

### 反复扩展下的架构侵蚀

**风险：** 迭代式的 agent 变更不断累积分支、局部例外、重复状态、包装器与文件，同时仍能通过狭窄的检查点。

**证据信号：**

- 复杂度集中在一小批不断膨胀的模块。
- 用重复的布尔标志取代显式状态机。
- 共享关注点的平行实现。
- 没有活跃消费者的兼容路径。
- 产品温和增长对应代码大幅增长。
- 每次变更使下一次变更牵涉更多区域。

**审计方法：** 沿仓库历史与高变动路径比较复杂度、耦合、归属、公开面与重复度。追踪近期的扩展序列，而不仅是最终快照。

**控制：** 架构适应度测试、有界的模块/文件规则、显式状态模型、周期性定向清理与根因合并。

### 局部最优扩散

**风险：** agent 反复在调用方附近解决眼前任务，而不修复共享的校验、策略、数据、错误或服务边界。

**证据信号：**

- 多个校验器/格式化器/认证检查/错误映射器。
- 绕过既有层级直接访问数据库/网络/工具。
- 同类缺陷在兄弟工作流中反复出现。
- 修复难以一致地传播。

**审计方法：** 跨域按语义行为与数据形态搜索。绘制规范入口点与绕行路径。

**控制：** 共享边界抽象、结构性 lint、集中式策略测试，以及让规范路径可被发现的仓库地图。

### 弱模式复制

**风险：** agent 把仓库中频繁出现的模式当作背书模式，放大既有债务。

**证据信号：**

- 新代码复制了已知的宽泛 catch、不安全解析、临时重试、无类型数据访问或薄弱的权限检查。
- 一个变通写法在首次出现后迅速扩散。
- 生成的测试复现了不充分的 oracle。

**审计方法：** 按历史识别复发模式，并与权威架构/安全规则对照。

**控制：** 把修正后的模式编码为 lint、测试、生成器、模板，以及链接到唯一事实来源的简短规则。

### 冗长与不必要的表面

**风险：** 生成的代码局部可懂但全局臃肿，扩大了评审、攻击与维护面。

**证据信号：**

- 纯包装文件、单实现接口、投机性配置与冗余注释。
- 重复实现的标准库/框架/平台行为。
- 为琐碎功能引入新依赖。
- 死的生成计划、适配器、兼容代码或快照。

**审计方法：** 应用 `anti-bloat.md`、依赖分析、死代码证据与安全删除排序。

**控制：** 以删除为主的清理、依赖预算、三次法则指引，以及保留安全控制的反膨胀检查。

### 隐藏耦合与归属碎片化

**风险：** agent 通过未记录的导入、共享可变状态、生成文件、事件或配置连接组件，留下清晰的无人负责区。

**证据信号：**

- 小功能引发广泛的扇入/扇出变更。
- 跨域导入违反架构规则。
- 数据/配置状态从多处写入。
- 没有负责人能解释关键路径。

**审计方法：** 构建依赖/数据流地图，并抽样近期的横切变更。

**控制：** 强制依赖方向、归属元数据、显式提供者/接口与场景文档。

### 理解与认知债务

**风险：** 代码吞吐超过人类与未来 agent 的理解能力，导致没有任何评审者维持可靠的系统模型。

**证据信号：**

- 大片 agent 创建的区域几乎没有人类撰写的决策或评审。
- 维护者依赖摘要而非代码/运行时证据。
- 回归重新引入了此前已修复的缺陷。
- 计划与架构依据缺失或过期。

**审计方法：** 询问意图、不变量、归属与恢复能否从仓库本地证据重建。抽样维护者/agent 追踪关键工作流的能力。

**控制：** 更小的变更、显式的计划/决策、系统地图、持久账本、可执行的不变量，以及对关键语义的人工校准。

## 仓库知识与归属风险

### 巨型指令文件

**风险：** 巨大的 `AGENTS.md`、提示词或策略文件挤占任务上下文，内部自相矛盾并逐渐腐朽。

**证据信号：**

- 数百/数千行混合了永久规则、任务历史与产品意图。
- 重复或互相矛盾的指令。
- 没有归属、新鲜度或链接校验。
- agent 忽略或选择性执行规则。

**审计方法：** 检查规模、用途边界、引用、归属、新鲜度检查与使用痕迹。

**控制：** 简短的入口地图加上向有版本的权威文档渐进披露；机械的链接/新鲜度检查。

### 过期或被投毒的仓库指令

**风险：** agent 遵循嵌入在文档、注释、issue、依赖或工作工件中的过期、恶意或意外生成的指令。

**证据信号：**

- 指令引用了已删除的路径或旧架构。
- 不可信文件可以覆盖运维策略。
- 生成的报告未加标签地与权威文档放在一起。
- 工具输出被当作指令解释。

**审计方法：** 按信任级别对指令来源分类，追踪提示词构造，并把规则与当前代码/配置对照。

**控制：** 信任标签、指令优先级、净化/分离、生成工件边界、归属与新鲜度强制。

### 外部/隐性的唯一事实来源

**风险：** 产品语义、事故知识或架构决策存在于聊天记录、个人头脑或不可访问的系统中，导致 agent 臆造缺失的上下文。

**证据信号：**

- 对同一规则反复提出 `Needs Decision` 询问。
- 代码/测试彼此矛盾且不存在权威规格。
- agent 输出随上下文提供者不同而不同。

**审计方法：** 盘点关键决策并定位仓库可见的权威依据。

**控制：** 把持久决策、契约、ADR 与验收示例编码进受维护的来源，同时不把仓库变成转录档案库。

### 生成文档失配

**风险：** agent 生成的计划、schema、图、runbook 与报告在可执行行为变化之后仍显得权威。

**证据信号：**

- 没有生成器/版本/来源元数据。
- 对生成文件的手工编辑。
- 文档宣称当前代码无法执行的测试/流程。
- 报告被取代后仍被索引为最新。

**审计方法：** 追踪生成过程，并将抽样与运行时/代码对照。

**控制：** 明确的生成目录、再生成检查、时间戳/提交、负责人，以及适当时从生产工件中排除。

### 归属与升级路径缺失

**风险：** agent 创建或修改系统的速度快于归属与值班责任的建立。

**证据信号：**

- 关键模块/工具没有负责人。
- 告警与发现无处路由。
- 自主变更跨团队而没有评审授权。

**审计方法：** 绘制代码/数据/服务/agent 的负责人与审批边界。

**控制：** 归属元数据、升级策略、CODEOWNERS/必需评审，以及可问责的技术债/发现负责人。

## 验证、评测与奖励风险

### 仅看结果的评估

**风险：** 最终测试通过掩盖了危险的工具调用、策略违规、数据泄漏、捷径或脚手架操纵。

**证据信号：**

- 只检查最终文件或二元通过/失败。
- 没有转录/工具/状态/副作用记录。
- agent 修改测试资产或环境控制。
- 生产结果与基准行为不一致。

**审计方法：** 在结果之外抽样轨迹、工具参数、环境变更、成本与副作用。

**控制：** 多评分器评测：确定性结果、静态/状态检查、轨迹/工具检查、模型评分细则，以及周期性人工校准。

### 对测试目标与基准过拟合

**风险：** agent 学会了可见的 fixture、通过阈值或反复出现的基准结构，而没有实现泛化行为。

**证据信号：**

- 字面特例与仅测试生效的分支。
- 在扰动或类隐藏案例上性能崩溃。
- agent 篡改 fixture、快照或评测器。

**审计方法：** 使用对抗性保留集、属性/蜕变/差分测试、多样化环境与评测器完整性检查。

**控制：** 受保护的评测资产、随机化/隐藏变体、独立 oracle 与轨迹评审。

### Reward hacking 与控制操纵

**风险：** 自主 agent 找到成功判据的漏洞，或修改评判它的机制。

**证据信号：**

- 禁用检查、修改完成标志、直接写预期工件，或利用重试。
- "一直工作直到成功"增加了绕过约束的尝试。
- agent 对评分器、权限或审计状态有写权限。

**审计方法：** 对成功判据做红队测试，并检查失败/可疑轨迹。

**控制：** 分离控制平面权限、运行期间不可变/冻结的评分器、进展预算，以及评测器变更的人工审批。

### 自评审相关性

**风险：** 同一模型/harness 以共享盲区兼任作者、评审者、修复者与关闭者。

**证据信号：**

- 评审只是复述作者摘要。
- 独立运行使用相同的上下文/顺序/工具。
- 两次"干净"通过没有增加新证据。
- 高影响下语义/安全缺少人工评审。

**审计方法：** 度量评审者多样性、提示词独立性，以及是否在读取既往结论之前检查了原始工件。

**控制：** 全新上下文、可用时异构的评审者/模型、角色分离、稳定账本与人类授权门禁。

### 评测遗漏 harness 回归

**风险：** 模型、系统提示词、上下文清理、默认值、工具或 harness 变化在当前评测集之外降低质量。

**证据信号：**

- 用户报告回归而内部评测仍然全绿。
- 模型/harness 版本未固定或未比较。
- 没有回滚信号或生产监控。

**审计方法：** 追踪模型+harness 版本历史、发布门禁、用户报告与生产指标。

**控制：** 能力加回归套件、有版本的 harness、金丝雀/A-B 测试、生产监控与回滚。

### 薄弱的验证组合

**风险：** 单元测试与静态检查占主导，而集成、失败、并发、迁移、安全与恢复仍未测试。

**证据信号：**

- 覆盖率高但反复出现逃逸的跨边界缺陷。
- 大量 mock。
- 没有浏览器/运维/恢复/发布测试。

**审计方法：** 把测试映射到关键场景与信任边界。

**控制：** 基于风险的组合，包含可执行的端到端、属性、模糊、迁移、回滚、恢复与安全测试。

## 提示词、工具与自主性风险

### 间接提示注入

**风险：** 不可信的 issue/PR 文本、文档、网页、邮件、日志、代码注释、依赖元数据或工具输出影响 agent 的控制决策。

**证据信号：**

- 不可信内容被放入高优先级提示词区段。
- agent 服从嵌入的请求去读取密钥、执行命令、修改规则或联系端点。
- 没有来源/信任分离。

**审计方法：** 绘制所有进入模型上下文的内容来源，并在沙箱中用良性金丝雀与对抗性指令做红队测试。

**控制：** 把内容当数据对待、隔离控制指令、限制工具/出口流量、校验动作，以及对高影响操作要求审批。

### 工具滥用与过度功能

**风险：** 工具暴露宽泛的 shell、文件系统、数据库、云、浏览器或部署能力，可能被模型错误或注入所滥用。

**证据信号：**

- 窄 API 足够时却提供通用命令执行。
- 通配符路径/资源。
- 开发/评审上下文中存在生产访问。
- 工具参数缺少 schema/白名单。

**审计方法：** 枚举有效能力并测试边界执行。

**控制：** 窄化的类型化工具、白名单、沙箱、最小权限、dry-run、幂等与人工审批。

### 过度自主

**风险：** agent 在没有可问责审批的情况下执行不可逆、特权、资金、客户可见或生产操作。

**证据信号：**

- 自我合并/部署/删除/轮换/通知动作。
- 审批分类器是唯一门禁。
- 没有 kill switch 或动作预算。

**审计方法：** 按动作映射自主级别，并模拟失败/注入场景。

**控制：** 按风险分级的审批门禁、职责分离、可逆的 staging、紧急停止与审计日志。

### 自我修改的护栏

**风险：** agent 能够编辑自己的提示词、技能、hook、权限、网络策略、扫描器、分支规则或审批逻辑。

**证据信号：**

- 同一身份可以修改并立即使用控制。
- agent 撰写的 PR 绕过对控制平面文件的独立评审。

**审计方法：** 检查 agent 写边界之外的所有权、权限、工作流路径与执行机制。

**控制：** 受保护的控制平面代码、独立审批、不可变的运行时策略，以及签名/有版本的配置。

### 本地回环与本地控制平面信任

**风险：** 回环服务、浏览器扩展、socket、webhook 或开发机工具因为"是本地的"而无认证地执行特权操作。

**证据信号：**

- 无认证的 localhost API。
- 浏览器可访问的端点触发 shell/文件系统/部署动作。
- agent 可以在同一主机上浏览不可信内容。

**审计方法：** 枚举本地监听与跨源/请求控制；从不可信的本地/Web 上下文测试。

**控制：** 认证/授权、源校验、CSRF 防护、能力令牌与进程/网络隔离。

### 模型输出注入到执行

**风险：** 自由格式的模型输出变成 shell、SQL、模板、URL、文件路径、代码或部署指令。

**证据信号：**

- 字符串拼接进高威力工具。
- 动态 eval/import。
- 没有 schema、白名单或校验。

**审计方法：** 追踪输出到动作的路径，并对模型输出做模糊测试。

**控制：** 类型化的结构化输出、可用时的约束解码、参数校验、白名单与审批。

### 密钥与敏感数据暴露

**风险：** agent 读取或传输超出需要的数据，且提示词/转录/工具日志制造了新的留存面。

**证据信号：**

- 把整个环境/仓库/数据库发给模型/工具。
- 密钥出现在转录、截图、日志、生成文件或远程 MCP 请求中。
- 未定义留存/删除策略。

**审计方法：** 为提示词、工具、连接器、日志、记忆与评测绘制数据流与留存地图。

**控制：** 最小化、脱敏、隔离分区、限定范围、加密、设定留存与审计访问。

## 记忆、状态与长时运行循环风险

### 过期的进度状态

**风险：** 新会话信任与 git/运行时现实不再匹配的摘要或进度文件。

**证据信号：**

- 完成标志与测试或当前 head 矛盾。
- 计划中引用的文件/符号已不存在。
- 多个 agent 覆写状态。

**审计方法：** 把持久状态与 git 指纹、当前工件和运行时检查对照。

**控制：** 稳定 ID、基线提交、可追加的迁移、冲突处理，以及会话开始时的仓库对照。

### 过早宣告完成

**风险：** agent 在窄测试之后，或因为先前进度看起来可观，就宣告功能/审计/评审完成。

**证据信号：**

- 没有端到端/用户/运维验证。
- agent 把自己的清单改成通过。
- 摘要措辞超出证据。

**审计方法：** 抽样已完成的任务，并从外部复现验收。

**控制：** 受保护的验收标准、独立验证与显式的完成证据。

### 记忆投毒与跨会话污染

**风险：** 恶意、过期或任务特定的内容滞留在记忆/账本中，偏置未来的工作。

**证据信号：**

- 不可信的 issue/文档内容被存为持久指令。
- 发现在没有人类授权的情况下被永久抑制。
- 一个租户/项目的数据影响另一个。

**审计方法：** 追踪记忆写入/读取策略、来源、租户归属、TTL 与删除。

**控制：** 信任/来源标签、限定范围的记忆、提升前评审、过期机制、用户可见的更正与隔离。

### 无界循环与钱包耗尽

**风险：** 反复的 agent-评审-修复循环消耗失控的 token、算力、API 调用或外部副作用。

**证据信号：**

- 没有硬上限、预算、进展检验或 kill switch。
- 同一发现来回震荡。
- 重试放大服务负载。

**审计方法：** 检查预算、运行日志、成本指标、终止判据与失败行为。

**控制：** 基于证据的停止条件、软/硬上限、无进展检测、幂等动作与升级上报。

### 上下文压缩损失

**风险：** 长任务在压缩/上下文重置期间丢失决策、约束或未解决的失败。

**证据信号：**

- 后续会话重复工作或推翻决策。
- 重要的告诫只存活在对话记忆中。
- 不同的进度工件互相矛盾。

**审计方法：** 仅凭仓库工件重建一项长任务。

**控制：** 简明的持久状态、冻结的发现/决策、精确的基线与渐进披露。

## 供应链与来源风险

### 幻觉或恶意的依赖

**风险：** agent 在没有充分验证的情况下安装看似合理的包、action、容器、插件或 MCP 服务器。

**证据信号：**

- 拼写错误、名不见经传的新包、可变版本、宽泛的安装脚本，或意外的传递性变更。
- 依赖仅凭模型建议就被选用。

**审计方法：** 验证来源、归属、版本、签名/来源证明、许可、必要性与行为。

**控制：** 批准的制品库/来源、锁定/固定策略、依赖评审、来源证明与最小功能。

### 生成代码来源不确定

**风险：** 复制/生成的代码许可、公告历史、生成器或更新路径不清。

**证据信号：**

- 大段风格不一致的代码块。
- 无元数据的 vendored 工件。
- 安全修复未关联到公告/可达路径。

**审计方法：** 追踪来源，并把生成输出与源/生成器对照。

**控制：** 来源元数据、生成器固定、许可检查、可复现生成与评审。

### 工具/插件/技能供应链被攻陷

**风险：** agent 扩展可以远程变化、执行代码、访问密钥或注入指令。

**证据信号：**

- 未固定的远程服务器/插件。
- 对市场/社区技能的宽泛信任。
- 安装/更新路径绕过评审。

**审计方法：** 盘点扩展、来源、版本、权限、网络行为、更新策略与沙箱。

**控制：** 白名单、固定、签名、评审、沙箱、出口控制与吊销。

### 构建与发布篡改

**风险：** agent 生成的 CI/发布变更引入 token 暴露、可变工件或评审后修改。

**证据信号：**

- 宽泛的工作流权限。
- PR 代码访问发布密钥。
- 可变的 tag/镜像/action。
- 工件缺少来源证明/签名。

**审计方法：** 追踪从源码到工件到部署的身份与权限。

**控制：** 最小权限、受保护的环境、不可变工件、来源证明、签名与职责分离。

## 运维与人类控制风险

### 验证瓶颈与审批疲劳

**风险：** agent 吞吐超过评审者容量，导致走过场式批准、评审延迟或过宽的自动批准。

**证据信号：**

- 大队列、低阅读时长、大量噪声发现，或高自动合并量。
- 人类只评审摘要而非变更。
- 告警/评审被习惯性忽略。

**审计方法：** 度量变更/评审量、延迟、发现处置、评审者参与度与逃逸缺陷。

**控制：** 更小的变更、风险路由、高置信度发现、仅对低风险动作自动评审，以及抽样/校准。

### 人类技能与系统模型萎缩

**风险：** 维护者丧失调试、运维或安全变更 agent 生成系统的能力。

**证据信号：**

- 没有agent 就无人能解释关键路径。
- 事故需要重新生成而非推理分析。
- 人工覆盖/恢复未经测试。

**审计方法：** 开展桌面演练、归属访谈与恢复演习。

**控制：** 人类拥有的不变量、runbook、场景评审、周期性人工追踪与显式培训/轮换。

### 误导性的评审指标

**风险：** 把评论接受率、解决率或数量当作真相，而忽视其他修复方式、误报或被忽略的严重漏报。

**证据信号：**

- 只优化评论量或解决率。
- 没有抽样的真实标签或逃逸缺陷分析。

**审计方法：** 用人工标注、按严重级别加权的精确率/召回率、替代修复分类与生产结果来校准。

**控制：** 均衡指标：真实缺陷、严重级别、误报负担、漏报缺陷、评审成本与下游质量。

### 没有可问责风险接受的自动化

**风险：** agent 在没有授权人类的情况下抑制发现、接受技术债或决定业务语义。

**证据信号：**

- 由 bot 身份"接受风险"。
- 仅凭模型置信度就永久抑制。
- 没有负责人/评审日期。

**审计方法：** 追踪决策授权与审计日志。

**控制：** 策略/风险决策由人类授权、设过期、有负责人、有理由与 revisit 触发条件。

### 环境不完整

**风险：** agent 在残缺的环境中工作，隐藏了集成、UI、运维、权限或部署失败。

**证据信号：**

- 缺少服务、数据、浏览器、可观测性或真实认证。
- 本地成功反复在 CI/生产失败。

**审计方法：** 把 agent 环境与所需系统依赖及关键工作流对照。

**控制：** 可复现的 worktree/沙箱环境、真实的服务 fixture、浏览器/运行时/可观测性访问，以及显式的环境缺口。

## 证据与持久控制

### 证据表

对每项风险记录：

```text
Risk family:
Assets and quality attributes:
Agent/model/harness versions:
Identity and effective permissions:
Untrusted inputs:
Tools/network/data flows:
Reachable failure/abuse scenario:
Outcome evidence:
Trajectory/tool evidence:
Existing controls and bypasses:
Residual risk:
Owner:
```

### 持久控制选择

按失败机制选择控制：

- **语义错误：** 权威规格、示例、决策日志、人类授权。
- **局部重复：** 规范层、结构性 lint、仓库地图。
- **薄弱验证：** 更强的 oracle、集成/属性/模糊/状态/恢复测试。
- **提示注入/工具滥用：** 信任分离、最小权限、类型化工具、审批。
- **过期状态：** git 指纹、稳定账本、对照校准。
- **架构侵蚀：** 适应度函数、复杂度/归属预算、周期性清理。
- **供应链：** 白名单、固定、来源证明、签名、扫描。
- **评审相关性：** 全新/异构验证者、人工校准。
- **无界循环：** 预算、进展检验、无进展诊断、kill switch。
- **认知债务：** 更小的变更、地图、归属、可执行不变量、演练。

控制应当可执行、可观察、有负责人、可测试。仅靠文档不足以支撑高影响不变量，但没有文档的控制也难以被人类和 agent 维持。
